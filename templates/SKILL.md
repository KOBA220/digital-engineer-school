# 共同開発の進め方

1. 対象プロジェクトのREADME、開発ルール、仕様書を読む。
2. タスクの目的・完了条件・変更範囲を確認する。
3. mainの最新を取得し、タスク専用の作業ブランチを作る。
4. 必要な変更を行い、プロジェクトに適した確認を実施する。
5. git diffで意図しない変更や秘密情報がないことを確認する。
6. 作業をコミットし、作業ブランチへpushする。
7. PRに変更内容・確認結果・未解決事項を書き、相手のレビューを受ける。
8. タスクの状態を更新し、議事録や仕様書にも必要な変更を残す。

## 報告形式
- 変更した挙動
- 確認した内容と結果
- 未接続・未実装の機能
- 次に必要な作業

## 制約
- APIキー、アクセストークン、パスワードをコードや資料に保存しない。
- PrivateのデータをPublicの資料・公開用ファイルに含めない。
- 接続していない機能を、利用可能と説明しない。
- 本番データの削除や権限の拡大は、対象と目的を確認する。
